# AI Evaluation Rubric (Reflexion-Derived)

These rules were automatically generated by the Multi-Agent Jury's Reflexion step on 2026-02-12.
They should be applied to future evaluations of the KiyasGO AI codebase.

## Rules

### 1. [CRITICAL] Security - Guvenlik Onlemleri
**Kural:** Guvenlik ve yanilsama denetimi icin yeterli onlem alinmasi.
- LLM ciktilari her zaman sanitize edilmeli.
- Prompt injection korumalari (input sanitization) eklenmelidir.
- Fallback mock yanit "gercek analiz" olarak sunulmamalidir.

### 2. [HIGH] Architecture - Teknik Borc Azaltimi
**Kural:** Teknik borcun duzenli olarak azaltilmasi.
- Mock data production koda karismamali, ayrilmali.
- Hardcoded degerler (fiyat esikleri, skor limitleri) config'e tasinmali.
- DecisionSynthesizer sinifi kucuk, tek-sorumluluklu sinflara ayrilmali.

### 3. [MEDIUM] Syntax - Ajan Agirliklandirmasi
**Kural:** Ajanlarin kendi uzmanlik alanlarina gore farkli agirliklar kullanmasi.
- Guvenlik ajani: %40 (en kritik)
- Sentaktik ajan: %30
- Mimar ajan: %30

### 4. [HIGH] Architecture - Degerlendirme Tutarliligi
**Kural:** Farkli ajanlarin ayni konulari farkli sekilde degerlendirmesinin onlenmesi.
- Ortak metrik tanimlari (rubric) olmali.
- Her ajan puanini AYNI olcekte vermeli (mutlak, goreceli degil).

### 5. [CRITICAL] Security - Uzun Vadeli Etkiler
**Kural:** Uzun vadeli etkilerin dikkate alinmasi.
- Cache poisoning riski degerlendirilmeli.
- LLM provider degrade oldugunda graceful degradation saglanmali.
- Rate limiting ve circuit breaker pattern'leri eklenmelidir.

## Application
When evaluating KiyasGO AI code in the future:
1. Always check for prompt injection vulnerabilities
2. Verify mock data is isolated from production paths
3. Ensure LLM fallback responses are clearly marked as "mock"
4. Apply weighted scoring: Security (40%), Syntax (30%), Architecture (30%)
5. Check for technical debt accumulation (hardcoded values, large classes)
